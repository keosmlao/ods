## 3. ແບບໃໝ່

### 3.1 ຫຼັກການ

1. **ໜຶ່ງໃບງານ ສອງເສັ້ນທາງ** — ໜ້າງານ (on-site) ແລະ ໃນສູນ (in-shop). ບໍ່ບັງຄັບເສັ້ນທາງໜຶ່ງໃສ່ອີກເສັ້ນທາງ
2. **ສະຖານະເປັນຄ່າທີ່ຂຽນຊັດເຈນ ບໍ່ແມ່ນຄິດຈາກ 12 ຖັນ** + ມີ **ບັນທຶກເຫດການ** ທຸກການປ່ຽນ
3. **ການລໍ = ທຸງ (hold) ຂະໜານກັບສະຖານະ** ບໍ່ແມ່ນຂັ້ນ — ວຽກລໍອາໄຫຼ່ ຍັງເປັນວຽກຂອງຊ່າງຄົນນັ້ນຢູ່
4. **ກົດໜ້ອຍລົງ ບັນທຶກຫຼາຍຂຶ້ນ** — ຂັ້ນທີ່ median = 0 ຊມ ໃຫ້ຍຸບເປັນເຫດການດຽວ
5. **ວັດ SLA ຢູ່ບ່ອນທີ່ເວລາຫາຍຈິງ** (§1.3) ບໍ່ແມ່ນຢູ່ບ່ອນທີ່ກົດງ່າຍ

**ຄິວ = state + hold** (ຕົວຢ່າງ `working + parts_purchase` = "ກຳລັງສ້ອມ ແຕ່ລໍຊື້ອາໄຫຼ່") ⇒ ບໍ່ຕ້ອງມີຂັ້ນ 5/6/7/14/15/16 ອີກ ແລະ ວຽກບໍ່ຫາຍອອກຈາກມືຊ່າງ.

### 3.4 ເສັ້ນທາງ ໜ້າງານ (IH/PS · 81% ຂອງງານ) — ກົດ 5 ເທື່ອ

```
ເປີດງານ ──► ນັດ + ຈັດຊ່າງ ──► [ແອັບ] check-in ໜ້າງານ ──► [ແອັບ] ຈົບງານ + ຮູບ ──► ເກັບເງິນ ──► ປິດ
  CS            CS/ຫົວໜ້າ            ຊ່າງ                    ຊ່າງ                CS       CS
 open        scheduled            working                work_done          billed   closed
                                      │
                                      └─ ຂາດອາໄຫຼ່ ⇒ hold=parts_* + ນັດຮອບ 2 (ຍັງເປັນ working)
```

- **ບໍ່ມີ** "ຮັບເຄື່ອງ / ສົ່ງຄືນ" ໃນເສັ້ນທາງນີ້ (ເຄື່ອງບໍ່ເຄີຍອອກຈາກບ້ານລູກຄ້າ)
- `ນັດ` **ບັງຄັບ** ⇒ ຄິວປະຈຳວັນ ແລະ SLA "ນັດ→ໄປຮອດ" ໃຊ້ໄດ້ຈິງ
- check-in + ຮູບຈົບງານ **ບັງຄັບຢູ່ແອັບ** (ມີກົນໄກແລ້ວ — `ods_job_checkin`, `ods_job_photo`)
- "ເລີ່ມສ້ອມ" ບໍ່ຕ້ອງກົດ — check-in ຄືການເລີ່ມ

### 3.5 ເສັ້ນທາງ ໃນສູນ (CI/ST/PS ຫຼັງໄປຮັບ · 19%) — ກົດ 6 ເທື່ອ

```
ຮັບເຄື່ອງ+ຮູບ ──► ບັນທຶກຜົນກວດ+ລາຄາ ──► ສ້ອມຈົບ+ຮູບ ──► QC ──► ແຈ້ງລູກຄ້າ/ສົ່ງມອບ+ເກັບເງິນ ──► ປິດ
   open            diagnosed              work_done      (ທຸງ)        billed              closed
                        │
                        └─ ລໍລູກຄ້າ/ອາໄຫຼ່ ⇒ hold, state ຍັງເປັນ diagnosed/working
```

- ຍຸບ "ເລີ່ມກວດ/ກວດຈົບ" ເປັນ **ບັນທຶກຜົນກວດເທື່ອດຽວ** (median ກຳລັງກວດ = 0.0 ຊມ)
- ຍຸບ "ເລີ່ມສ້ອມ/ສ້ອມຈົບ" ເປັນ **ບັນທຶກສ້ອມສຳເລັດ** (92% ກົດພາຍໃນ 5 ນາທີ)
- QC ເປັນ **ທຸງຂອງ `work_done`** ບໍ່ແມ່ນຂັ້ນແຍກ (median ລໍ QC = 0.0 ຊມ)

### 3.6 ໂຄງຂໍ້ມູນ

```sql
-- ສະຖານະປັດຈຸບັນ (ຂຽນຊັດເຈນ ບໍ່ຄິດເອົາ)
alter table tb_product add column state varchar(20);      -- open|scheduled|diagnosed|working|work_done|billed|closed|cancelled
alter table tb_product add column state_at timestamp;      -- ເຂົ້າສະຖານະນີ້ເມື່ອໃດ (ໂມງ SLA ນັບຈາກນີ້)
alter table tb_product add column route varchar(10);       -- onsite | inshop  (ຄິດຈາກ service_type ຕອນເປີດງານ)

-- ທຸງລໍ — ຫຼາຍອັນພ້ອມກັນໄດ້
create table ods_job_hold (
  id bigserial primary key,
  workflow varchar(10) not null, job_code varchar(20) not null,
  hold varchar(20) not null,               -- parts_warehouse | parts_purchase | customer | approval
  opened_at timestamp not null default localtimestamp(0), opened_by varchar(50),
  closed_at timestamp, closed_by varchar(50), note text
);

-- ບັນທຶກເຫດການ — ແຫຼ່ງຄວາມຈິງດຽວຂອງປະຫວັດ
create table ods_job_event (
  id bigserial primary key,
  workflow varchar(10) not null, job_code varchar(20) not null,
  at timestamp not null default localtimestamp(0), actor varchar(50),
  event varchar(30) not null,              -- open|schedule|arrive|diagnose|work_done|qc_pass|bill|close|cancel|hold_on|hold_off
  from_state varchar(20), to_state varchar(20), source varchar(10),  -- web|app|erp|system
  note text
);
```

ຖັນເວລາເກົ່າ (`time_check`, `time_repair`, …) **ບໍ່ລົບ** — ຂຽນຕໍ່ໄປໃນໄລຍະຫັນປ່ຽນ ເພື່ອບໍ່ໃຫ້ລາຍງານ/ແອັບພັງ.

## 4. ແຜນຫັນປ່ຽນ (ບໍ່ຢຸດລະບົບ)

**P0 — ຢຸດເລືອດ (1-2 ມື້, ບໍ່ແຕະໂຄງສ້າງ)**
- ກົດ "ສ້ອມສຳເລັດ" ໂດຍບໍ່ໄດ້ກົດ "ເລີ່ມສ້ອມ" ⇒ ຕື່ມ `time_repair` ໃຫ້ເອງ (ຢຸດ 367 ໃບ "ຈົບກ່ອນເລີ່ມ")
- IH: **ບັງຄັບວັນນັດ** ຕອນເປີດງານ/ຈັດຊ່າງ (ດຽວນີ້ 4%)
- ແອັບ: ບັງຄັບ check-in ກ່ອນ "ຈົບງານ" ສຳລັບ IH (ກົນໄກມີແລ້ວ — `requireCheckin`)
- ຕັ້ງເຕືອນອັດຕະໂນມັດ: ວຽກເປີດເກີນ 30 ມື້ (ດຽວນີ້ 15 ໃບ ເກົ່າສຸດ 350 ມື້)

**P1 — ວາງໂຄງ (1 ອາທິດ, ບໍ່ປ່ຽນໜ້າຈໍ)**
- ສ້າງ `state`, `state_at`, `route`, `ods_job_hold`, `ods_job_event`
- backfill: ຄິດ state ຈາກຖັນເວລາເກົ່າ (mapping §3.2) + ສ້າງ event ຍ້ອນຫຼັງຈາກ timestamp ທີ່ມີ
- **dual-write**: ທຸກ action ຂຽນທັງແບບເກົ່າ ແລະ ແບບໃໝ່ · `STAGE_SQL` ຍັງເປັນຕົວຕັດສິນ (ບໍ່ມີຫຍັງປ່ຽນສຳລັບຜູ້ໃຊ້)
- ກວດຄວາມຕົງ: ລາຍງານປຽບທຽບ state ໃໝ່ ທຽບ ຂັ້ນເກົ່າ ທຸກມື້

**P2 — ປ່ຽນວິທີເຮັດວຽກ (2-3 ອາທິດ)**
- ໜ້າຈໍ 5 ຄິວໃໝ່ (§3.8) + ຄິວປະຈຳວັນຂອງຊ່າງເປັນຕົວຕັ້ງ
- ຍຸບປຸ່ມ: ເລີ່ມ/ຈົບ ກວດ → ອັນດຽວ · ເລີ່ມ/ຈົບ ສ້ອມ → ອັນດຽວ
- hold ແທນຂັ້ນ 5/6/7 · SLA ໃໝ່ 4 ຈຸດ (§3.7)
- `STAGE_SQL` ກາຍເປັນ **view ຄວາມເຂົ້າກັນໄດ້** (state → ເລກຂັ້ນເກົ່າ) ⇒ ລາຍງານ · KPI · ແອັບ Flutter ຍັງແລ່ນໄດ້

**P3 — ເກັບກວາດ (ຫຼັງໃຊ້ຈິງ 1 ເດືອນ)**
- ຖອດຂັ້ນ 13-16 (ເຄມ 2 ໃບ/ປີ) ໄປເປັນ hold `approval` + ປະເພດງານ
- ລົບຖັນຕາຍ: `repair_appoint_date`, `pickup_start`, `master_product`, `spare_order_finish`, `warranty_reason`
- ຍ້າຍລາຍງານໄປອ່ານ `ods_job_event` (ໄດ້ "ເຂົ້າ/ອອກຂັ້ນເມື່ອໃດ" ຈິງ ເປັນເທື່ອທຳອິດ)
